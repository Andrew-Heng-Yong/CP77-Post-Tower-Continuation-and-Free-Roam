## Native behavior

- **Normal reload recreates the scheduler entry first.** DelaySystem's load routine at RVA `0x1133B2C` builds a timer of the saved kind with the saved scheduler ID and remaining seconds. Its insertion call at `0x1133D42` puts that entry into the delay queue at the correct point relative to existing deadlines. DelaySystem's save collector at `0x2AAC3D4` reconstructs the remaining seconds from relative scheduler intervals and emits a 16-byte row before serializing it. The observer reads that native result after the collector returns.
- **The quest reload job resolves and reattaches the original handler.** It resolves saved registrations to graph paths and uses the native mode 2 context and synthetic root. The registration path looks up the original logical node and uses its existing slot when present. A missing match follows the normal registration allocator. A fresh slot alone does not account for old pending work addressed by slot index. The dispatcher assumes prepared resources, a valid graph context and the quest job's thread-local state.
- **The handler has two timer paths.** The initializer at `0x1948BC` reads its node-instance mapping. With no mapping it schedules the authored duration. With a mapping it looks up the corresponding native timer and attaches its callback. Rejected attachment goes through the same native ready notification used by expiry. The fixture's scheduler ID is `0000000402488C23`. Its node-instance map stores the same two words in the opposite order, `02488C2300000004`.
- **Timer cancellation and timer removal are separate events.** Native uninitialization removes the node mapping and queues a cancellation. In the delay worker at `0x1AA46C`, the cancellation loop calls `0x1AA7D0` before the expiry pass. A successful match erases the slot and transfers its interval to the following timer to preserve the other deadline. The expiry pass calls the timer before removing the slot through that same function. An erased slot therefore establishes removal only. Callback delivery and outstanding quest notifications need their own proof.
