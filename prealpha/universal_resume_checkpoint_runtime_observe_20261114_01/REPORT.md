The supplied ManualSave-28 screenshot shows Northside with “Find the Delamain cab in Northside.” The 21:49:08 reload log reached `Ready | All required setup checks passed.` This supports Northside's visible persistence through this specific save and reload, not execution-state continuation.

The screenshots alone do not establish when those entries changed state or whether any rewards or saved owner states changed. The log shows the checkpoint-unavailable event while 2x was active and `UnsetTimeDilation(CETSpeed)` before q307 finished. This sequence does not identify time dilation as the cause of checkpoint unavailability.

The live log shows that fact changed `0 -> 1` at 21:19:42, five seconds before the unavailable message. The reflection call and native capture have silent empty-return paths, so the exact rejection point is not known from this log.
