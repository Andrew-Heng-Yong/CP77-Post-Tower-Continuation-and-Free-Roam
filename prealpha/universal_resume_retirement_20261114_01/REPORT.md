## Quest notification handoff

The pinned 2.5 engine copies and deduplicates physical indices from the shared notification queue in `0x3534DC`, clears that queue, then acquires the graph lock to resolve each index. A copied notification has no original handler identity. Native retirement clears the row, invokes the native shared-queue removal and returns the index to the free list. The removal takes one matching shared entry. Registration `0xEB6B3C` can reuse that index immediately.

The prototype wraps native retirement for a selected registration and reserves the cleared index before the next registration. Once the caller has proved that its old callback producers have stopped, it removes all matching shared notifications under the existing queue lock and waits for a subsequent complete notification pass before returning the index. It preserves the order of unrelated notifications. An observed late enqueue starts a new wait. A changed quest-system session or conflicting registration defers the handoff. [Implementation](RetiredQuestSlot.hpp)

The fixture interleaves retirement after the native worker has copied the old index and released the queue lock. Duplicate entries in the shared queue make native retirement skip its deferred marker. An intervening native registration still receives another index. The original batch exits without resolving the retired row, then native registration can reuse it. The reload control executes the native free-list rebuild against a cleared row and clean queue. Native reload will rebuild that availability from the row, so the live integration must keep full saves outside the interval in which a retired callback can still enter the saved queue.
