# Resume any phase of a restored quest

The target is one shared system that continues the original quest from its saved execution state. The system needs the exact active waits, pending branches, timer state, and owners. A journal objective is one observation and often covers several native waits or multiple concurrent branches. The five staged gig entrances are useful for existing saves with the corresponding earned objective. They provide fixtures for the shared system. [Current staged entrances](../resume_dispatcher_rd11_minefield_20261114_01/REPORT.md)

## Native state the prototype can identify

The same reader resolves saved handler registrations for all six pinned bodies using the saved resource index, phase path, original node ID and registration type. It uses the 830 current consolidated ArchiveXL bindings and two other hash-matched registration providers for the captured inputs. It reproduced 122 prior owner comparisons across the original three preservation controls and the six interrupted gigs. This confirms the saved addresses. Registrations alone do not establish what is executing in a live session. [Reader](read_handlers.py) · [Saved registration comparison](evidence_02/assessment.json)

In Manual Save 26, 9,526 registrations bind to source and 575 remain unresolved. The separate timer reader joins the native node-instance map to the exact saved timer IDs. It recovered nine direct real-time delays and thirteen direct game-time delays in that pre-Tower save. One ten-second Kabuki delay had about 8.95 real seconds remaining. The saved `sq029` message delay had 339,888 game seconds remaining of the 864,000 originally scheduled. Seven malformed timer controls rejected truncation, trailing bytes, duplicate identities and a nonfinite duration. These are offline saved values, with no claim of elapsed-time accuracy after a live suspend and resume. The parser is pinned to the tested timer record layouts and the current executable. Nested timer branches, other record variants and unbound providers still need support. [Timer reader](read_timers.py) · [Remaining-time readback](evidence_04/timer_binding.json)

## Implement the shared lifecycle

1. Capture the actual execution state for eligible quests at the native pre-cleanup boundary. Include the original graph identity, pending inputs and branch latches, remaining delays, in-flight scene or call state, and support ownership. Use the native quest thread or an engine-owned save boundary. The existing manually called inspector has an unresolved startup and teardown race. The exact checkpoint must be tied to the ending session that produced it. The existing global-latest file can continue to supply historical evidence to the installed stage adapters. [Native lifecycle evidence](../quest_restoration_qr15/saved_graph_state_01/inspector_review_01/REPORT.md)
2. Qualify selective suspension and restoration at the original native addresses. Keep The Tower's genuine finish and unrelated retirement. The base game terminates a parent, and EP1 cuts a parent and retains some alternate companion handlers. Preserve or rebind the affected support leases and suppress callbacks during the ending. Record real-time and game-time delay values independently of the removed timer handles. Normal save reload has a native path that resolves saved handler addresses, prepares their resources and reuses their registration slots. Investigate that path for selective reattachment in the retained session. It still needs a verified lifecycle and exactly one callback per qualified wait with the captured remaining duration. [Base and EP1 shutdown](../handler_preservation_hp1_20261112_01/REPORT.md) · [Native freezer and delay behavior](../handler_preservation_hp2_20261112_01/REPORT.md) · [Saved handler reload path](../quest_restoration_qr15/event_stage_01/quest_handlers/REPORT.md)
3. Connect qualified native continuation to the existing dispatcher. One owner per quest or cooperating family inherits the saved state and existing completion and payout paths. Route that owner through the approved Johnny edits while preserving saved addresses. Keep completed and genuinely failed histories, the existing inactive entries, and installed stage adapters for older saves whose exact state is gone. Where state is incomplete, defer the exact handoff and let a reviewed stage adapter decide eligibility. The registry supplies provider and ownership data in bulk. Exceptions are defined by unsupported handler types, resource variants or shared owners, including the active hatch companion in Treating Symptoms. [Dispatcher and guards](../resume_dispatcher_rd1_20261112_01/REPORT.md) · [Saved companion evidence](../resume_dispatcher_rd5_gigs_20261113_01/evidence_01/companion_review.json)
4. Prove the shared mechanism first with one partially elapsed timer of each clock type, one ordinary fact or interaction wait, and one pair of concurrent waits. Verify one callback after resume, save and reload while suspended and resumed, and persistence of the original branch latches. Then exercise a real base and EP1 owner through genuine Tower completion, watch for duplicate rewards and preserved Johnny edits, and expand by handler class using automated source and save fixtures. This gives broader evidence without requiring the player to test each quest.

This is the offline foundation for the shared lifecycle. It reads original continuation state and timer values. Runtime capture at the ending boundary, selective owner suspension, callback reattachment, scene continuity and native reload still require implementation and qualification. All test inputs are read-only. RD10 is the installed build.
