# Post-Tower arm refresh retest

The user reported that the CET UpperBody and hand equipment requests after Photo Mode did not restore the arms. Several manual Photo Mode cycles also failed to clear the remaining view defect. The earlier vehicle round trip while Immersive First Person was suspended remains the confirmed in-session recovery for both the torso and arms. [Earlier vehicle observation](post_tower_body_view_isolation_20261116.md) · [Installed test](../prealpha/tower_arm_refresh_20261117_01/REPORT.md)

The 17 November 12:45 Toronto game log records the stock hand attachment request and confirmation, followed by the three arm event requests. The automatic Photo Mode request followed 0.391 seconds later on the engine clock. The log records the menu showing, the normal exit request, the menu hiding, the return to V's gameplay camera and the setup cover release. Attachment confirmation reads the item slot. The manual retests and rendered view are user-reported.

The matching vanilla vehicle exit also clears vehicle camera and animation inputs and resumes other player state machines. Its passenger animset reset requires a real vehicle mount. The matching vanilla return to exploration sends `AnimFeature_SceneSystem.tier = 0` to the `Scene` animation input. The final Tower cutscene enters Tier 5. The handoff diagnostic read Tier 1 after setup, while the animation input itself was unmeasured. Reapplying the exploration input is a narrow on-foot test of that animation path. The console transport uses the native event helper, and gameplay verification is pending.
