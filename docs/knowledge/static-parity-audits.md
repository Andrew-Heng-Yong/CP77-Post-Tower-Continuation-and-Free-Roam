## A2 — Required audit method

**Status:** acceptance design for the future auditor, not a current parity result.

1. Pin current installed package/source and native provider precedence. Separate real vanilla, modified official depots, private copies and raw historical caches.
2. Reconcile the audit denominator: selected/excluded/conditional/held quests, exact native IDs, gig/side/minor/repeatable families. Entry catalogue totals are not stage coverage.
3. Build recursive phase and scene dependency closure. Resolve handles, actual entry sockets, nested graph edges, cut/termination paths and unreachable branches. Missing data stays UNKNOWN rather than disappearing from totals.
4. Map entry/admission, native progress and parent ownership; actor/community/prefab/variant/workspot/camera/marker dependencies; phone/message request-handler-ack chains; cleanup and shared leases; outcomes, rewards/counters/vehicles; saved identities and reload obligations.
5. Compare normalized vanilla/private graphs with an explicit allowlist of intentional differences: Tower handoff, R4 voice/presentation, eligibility/history safeguards and documented bounded adaptations. Do not count those as silent parity successes or mechanically “repair” them back to vanilla.
6. Test negative controls from actual past failures: discarded CR1 donor; lost nested edges; wrong relative/full NodeRef; missing root studio prefab; missing initializer/cleanup; deadlock on a call's own interruption flag; generated-ID collision with no depot collision; unreachable Meredith branch; ambiguous original owner; repeated reward; opaque sector.
7. Emit classifications with evidence: PASS within named scope, intentional deviation, confirmed gap, conditional, blocked/opaque, unknown or live-only. Include resource/hash/graph/node/socket references, rationale and confidence. Static PASS must not certify gameplay or an arbitrary saved-owner state.

**Expected outputs:** machine-readable provider/resource manifest, normalized graph/dependency index, source-to-private mapping, intentional-difference registry, per-quest/per-stage findings, unresolved data list, regression results and a concise report. Include hashes, tool versions and deterministic inputs so another run can reproduce the conclusions.

**Verification:** fail closed on missing/decode-unsupported resources, dangling handles, unexamined optional branches and unsupported YAML; check completeness of traversal and denominator independently. Keep source-only defects separate from user-observed failures. No game/save/fact writes, installations or package changes belong to static auditing unless a later task expressly changes scope.

## A3 — Runtime follow-up boundary

**Prerequisites:** a separate authorized gameplay/repair task and appropriate disposable fixture. **Expected evidence:** exact route, outcomes, interruptions, save/reload and reward uniqueness, not just “quest appears.” **Verification:** preserve master saves and compare actual ownership/history. Static auditors should list these follow-ups rather than ask the user to replay every quest or mutate facts to manufacture a PASS.
