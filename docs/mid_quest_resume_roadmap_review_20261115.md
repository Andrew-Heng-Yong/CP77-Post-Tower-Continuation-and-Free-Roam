The revised next work is:

1. **Classify and choose an in-scope fixture.** Reuse RC2 and saved/cutoff evidence. For each proposed state, record the selected type, full cooperating owner set, pending callbacks/joins, support and reward obligations, exclusion reason if any, and evidence level. Review a small contained collection or travel boundary first. The Gig is a useful precedent, but a new native fixture must prove its original pre-cleanup owner and coordinate with the already-installed Cassius adapter. Neither MS31 nor a historical autosave slot automatically qualifies a new test.
2. **Generalize the shared plan while enforcing scope.** Carry forward proven native primitives into a fresh successor. Replace the active fixed Falco selection with source-bound supported plans, leaving the excluded pilot and its evidence preserved. Bind actual resource identities and approved Johnny-edited routes. Keep legacy adapter receipts and save-local fields stable. A fact, journal or timer handler class alone cannot distinguish an allowed objective from an excluded phone branch.
3. **Close the transition and owner gaps.** Recheck scope at the actual interruption state and before restoring it. If a timer expires naturally into an excluded pending state before retirement, defer the affected family instead of recreating the old timer or restoring the excluded successor. Arbitrate between original, replacement and existing private owners so a resumed family has one controller. A failed partial handoff must unwind before any eligible fallback can claim ownership. Review support readiness, source-bound journal continuation and progression gates; a saved registration or Failed journal alone does not decide the outcome. Preserve genuine failure and only use reviewed handling for verified Tower interruption.
4. **Qualify the four types through the shared mechanism.** Start with one contained stage that visibly advances after genuine completion and survives a new save/reload. Expand to simple timers and supported parallel objectives using the same mechanism. For timer support, qualify both clocks, remaining-time and natural-expiry cases; expiration is not permission to skip the successor's prerequisites. Parallel checks preserve earlier branch inputs, remaining objectives and the final reward exactly once. Group compatible samples in one meaningful mixed-progress run when their fixtures are ready.
5. **Record bounded acceptance and omissions.** Cover all four selected types, base-game and EP1 cases, plus inactive, terminal, excluded and existing-owner controls. Use offline negatives for the relevant races, duplicates and unsupported states, then targeted live/reload observations. Keep Hanako route status separate from the passed Reed capture. No phone-stage repair or excluded mid-action restoration is a release requirement. Do not mark the shared feature complete from helper tests, catalogue size or legacy adapter successes.

Native freezer support is not a shortcut: the HP2 engine trace showed that removal can cancel timers and reinitialization without the saved mapping uses the full authored duration. Likewise, suppressing Tower cleanup is not the selected solution. Keep genuine cleanup and use qualified transfer for supported pending state. [Freezer finding](../prealpha/handler_preservation_hp2_20261112_01/REPORT.md)

The immediate deliverable is a source-bound four-type admission plan and a qualified next fixture, followed by a fresh implementation candidate. No new game test is ready from this review alone. This work updates planning and documentation only; it does not change runtime code, deployed files, saves or historical test artifacts.
