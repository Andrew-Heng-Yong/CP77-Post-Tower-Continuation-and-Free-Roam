## Complete preserved-source index

The original AGENTS, PROJECT, ROADMAP and README are retained byte-for-byte under `docs/history/instructions/2026-10-29/`. `originals.json` records original size/hash and snapshot location; preservation verification rehashes every snapshot.

[`traceability.csv`](traceability.csv) and [`traceability.json`](traceability.json) index **all 1,311 original paragraphs**, including **812 paragraphs flagged for critical wording**. Each has its original file/line interval, exact archived location, text hash/excerpt, topic destination and a disposition explaining condensation or removal from automatic instruction loading. Every paragraph has an existing topic destination and preserved source. Historical component specifics remain in the exact source and history index; they were not silently generalized into standing permission.

Topic routing and critical-word flags are heuristic navigation aids, not proof that text with similar words has identical meaning. The manual matrix below reviews the important permanent safeguards, while the conflict register makes actual supersessions and unresolved decisions explicit. The byte-preserved originals are the fallback for every detailed investigation constraint and datum, including statements not matched by the critical-word filter.

## Why the loading behavior changed

The root contained 288 “Latest” blocks and duplicated status/policy across three large guides. Exact text analysis found 22 duplicate paragraph groups and 50 repeated instances beyond the first; semantic repetition is broader and is not given a fabricated percentage. Many installation holds and future test requests were specific to retired candidates. Keeping them all active made agents reread obsolete inputs, retry pinned scripts, confuse old counts with current state and ask for already-completed tests.

The new root links by task to current-state and knowledge pages. Six nested AGENTS files cover docs/prealpha/profiles/redscript/release/tools. Archive and research guidance is in the tracked knowledge base because those data trees are Git-ignored. Third-party `CLAUDE.md` and vendored Cargo configuration are inventoried but not promoted into project authority. Global Codex instructions/configuration and unrelated historical documents were not edited.
