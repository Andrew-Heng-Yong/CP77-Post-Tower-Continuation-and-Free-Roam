# Post-Tower body-view isolation — 16 November 2026

This follow-up records the user's live tests after the [BV1 and IFP retest](post_tower_body_view_retest_20261116.md). It is a bounded observation, not a confirmed cause or a gameplay fix. No Core, IFP, save or game file was changed in this investigation.

With the first-person view broken, the user suspended Immersive First Person (IFP) through its session-local `api.Disable("PTFRDiagnostic")`. The holstered torso then looked normal, while the holstered arms remained invisible. With a weapon drawn, the torso remained distorted and the arms remained invisible. This shows that IFP contributed to the holstered camera/body appearance in this run, but its ownership alone does not explain the missing arms or drawn-weapon view.

The user then ran `AnimationControllerComponent.ApplyFeature` on V with fresh `AnimFeature_CameraBodyOffset` and `AnimFeature_CameraGameplay` objects. CET printed `bodyOffset=true nil gameplay=true nil`; the user saw no visual change. These results show that the calls completed without a Lua error, not that they reached every animation graph affected by vehicle exit.

While IFP was still suspended, the user entered a vehicle in third-person view and exited. The holstered and weapon views, including both visible arms, returned to normal. This is a user-reported pass for that one vehicle round trip. It strongly separates the recovery from IFP re-enabling and from the two direct feature calls. It does not identify which native vehicle transition caused recovery, or prove that the short loading interval did so.

The matching vanilla script cache shows that `DriveEvents.OnExit` resets the two camera features and calls `ResumeStateMachines`. That helper queues `PSMStartStateMachine` for UpperBody, Equipment RightHand, Equipment LeftHand, CoverAction, Stamina, Locomotion, Crosshair and CameraContext. `ExitEvents.OnEnter` also unmounts V, clears the vehicle animation feature, resets the vehicle blackboard and restores camera bobbing. See [the exact source](../prealpha/quest_restoration_qr15/lifecycle_01/script_source/current_01/base.script) at `DriveEvents` near line 547238, `ResumeStateMachines` near line 282384 and `ExitEvents` near line 550917. The UpperBody and hand equipment restarts are a focused next diagnostic lead, not established as the defect.

At the next broken-view reproduction, with IFP suspended and before entering a vehicle, queue only the vanilla UpperBody start event once. Compare the holstered and drawn views immediately. If it changes nothing, test the two Equipment hand starts separately in a later step.
